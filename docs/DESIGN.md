# 设计说明

写给未来的自己，解释为什么是这样而不是那样。

## 一句话

**规则决定「说不说」，模型决定「怎么说」。**

这是整个项目最重要的一条约束。所有触发逻辑都在 `agent/rules.py` 里，是纯函数，
不联网、不看时钟（时间由调用方装进 `Snapshot`）。模型只做两件有边界的事：

1. 把一段口语描述拆成结构化任务（`plan_tasks`）
2. 把规则生成的提醒文案改写得像人话（`rewrite_nudge`）

这样带来三个好处：

- **断网可用**。`LLMUnavailable` 一抛，`Planner` 立刻落回规则文案，用户无感。
- **可测**。规则是纯函数，`tests/test_rules.py` 不需要 mock 任何东西。
- **可预期**。不会出现「模型今天心情好，一小时弹了六次」。冷却时间是硬编码的。

## 分层

```
ui/          ← Qt，唯一知道界面存在的一层
  ↓ 调用
agent/       ← 决策：规则 + 模型
  ↓ 读写
core/        ← 领域模型 + SQLite
scheduler/   ← 时间与输入状态（不依赖 Qt）
config.py    ← 所有可调参数
```

依赖方向单向向下。`core` 和 `scheduler` 不 import Qt，也不 import `agent` ——
所以它们能在没有图形环境的地方跑测试。

## 为什么 Snapshot 是个 dataclass

规则函数长这样：

```python
def _rule_take_a_break(s: Snapshot) -> Nudge | None: ...
```

而不是这样：

```python
def should_take_break(store, tracker, config, now): ...
```

因为一旦规则自己去 `store` 里查数据、自己调 `datetime.now()`，测试就得起数据库、
打时间补丁。`Snapshot` 把「取状态」和「判断」切开了：`ui/app.py` 负责取，
`rules.py` 负责判断。加一条新规则时不用碰任何 IO 代码。

## 为什么专注时长是状态机而不是简单计时

`FocusTracker` 有三个阶段：`AWAY` / `FOCUS` / `BREAK`。关键在于 `AWAY` 的处理：

- 离开电脑（idle 超阈值）时，**不累计**专注时长 —— 否则去吃个饭回来会被告知
  「你已经连续工作 3 小时了」。
- 但也**不清零** —— 去倒杯水回来还算同一段专注。
- 只有离开超过 `reset_after_away_minutes`（20 分钟）才真正重新计。

另外 `tick()` 里丢弃了 elapsed > 10 分钟的时间片，处理系统休眠和时钟跳变：
合上笔记本三小时再打开，不该被当成专注了三小时。

## 为什么每 20 秒 tick 一次，而不是用定时任务

番茄钟的精度要求是分钟级，20 秒足够。用轮询而不是「45 分钟后触发一次」是因为
用户随时可能离开电脑 —— 定时器不知道这件事，轮询才能把 idle 状态算进去。

代价是每 20 秒会问一次 Planner。当有 API key 时这可能触发网络调用，
所以 `_NudgeWorker` 跑在后台线程，并且用 `self._worker is not None` 挡住并发。
真正会走网络的时刻很少 —— 规则先跑，没有候选提醒就直接返回 `None`，
只有确实要弹提醒时才调模型改写文案。

## 为什么 SQLite 而不是 JSON 文件

一开始确实可以用 JSON。选 SQLite 是为了 `nudge_log` 表 ——
冷却逻辑要查「上一次这类提醒是什么时候」，这种带条件的时序查询用文件写起来很难看。
顺带也让「导出我这一个月的专注数据」变成一句 SQL。

没上 ORM 是因为表就四张，手写 SQL 比引入 SQLAlchemy 的依赖划算。

## 提示词的位置

全部在 `agent/prompts.py`，包括 JSON schema。调提示词不用翻业务代码，
也不会在改逻辑时不小心动到文案。

结构化输出用的是 `output_config.format` 的 json_schema，不是让模型「输出 JSON」
然后正则抠 —— 后者在中文场景下尤其容易翻车。

## 界面上的取舍

- **没有主窗口**。应用活在托盘里，只有被叫到时才出现。规划应用最讨厌的就是
  「你得先打开它」。
- **提醒是气泡不是弹窗**。不抢焦点，不打断正在输入的东西，鼠标移上去会暂停消失倒计时。
- **图标是画出来的**。`style.py` 里用 QPainter 画一个 "jo" 方块，
  省掉打包资源文件这件事。

## 已知的粗糙处

- 任务和番茄钟还没绑定 —— `WorkSession.task_id` 字段有了，但 UI 上还没有
  「选中任务再开始计时」的入口。
- 目标进度只能手动 bump，没有「完成关联任务时自动推进」。
- 跨天重置只在 tick 里检查日期变化，如果程序在午夜前后休眠，第一次 tick 才会重置。
